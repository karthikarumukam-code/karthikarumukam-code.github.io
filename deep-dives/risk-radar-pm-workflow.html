The PM Workflow

Two layers, read together: where the tool sits inside a PM's real reporting cycle, and what actually happens once they open it. Both are drawn from the shipped prototype, not a proposed design.

Inside the app

The five steps a PM actually walks through once they open the tool.

1

Select a project

Intent
See this project's current risk picture
Interaction
Sidebar project switcher (5 demo projects), or upload your own documents
Response
Loads the project's documents and its computed risk snapshot
Gap

A project with no documents has no designed empty state yet.

2

Read the dashboard

Intent
Understand overall health quickly
Interaction
Health badge, risk counts, the PM's own reported RAG shown next to the AI assessment
Response
Any divergence between the two is surfaced explicitly, never hidden
As designed

The sharpest built case: a project reported AMBER by its PM, assessed RED by the tool — a real divergence, not staged.

3

Inspect a risk

Intent
Decide whether to trust and act on a flag
Interaction
Expandable "why this was flagged" on each risk
Response
Shows the exact source sentence or RAID row that triggered it
Confirms intent

The healthy-project case (no open risks) proves the tool stays quiet when nothing is actually wrong.

4

Compare over time

Intent
See whether things are getting better or worse
Interaction
Trend chart built from the project's historical weekly status reports
Response
A per-week signal-count bar chart
Known limit

The count includes good-news mentions too — read it as a secondary diagnostic, not the primary signal.

5

Switch extraction method

Intent
Compare the rule-based baseline against LLM-assisted extraction
Interaction
Sidebar provider dropdown: rule-based / Anthropic / OpenRouter
Response
Re-runs extraction on the same documents with the selected method
Unverified

The LLM providers have real code but have never run against a live API key in this environment — don't demo this state as validated.

Every step above is what the shipped prototype does today, not a proposed design — see the "as built" user journey and reporting-cycle map for the full reasoning.
